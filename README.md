# keenetic-bootstrap

Скрипт для Keenetic с entware, который настраивает раздельную маршрутизацию: по умолчанию трафик идёт
через отдельные подключения (VPN), а российские диапазоны адресов — напрямую через интерфейс провайдера.
Ставится одной командой, в том числе заново после сброса роутера и очистки флешки.

## Что нужно заранее

- Keenetic с установленным entware (компонент «Поддержка открытых пакетов», флешка или встроенная память).
- **Основное подключение к интернету — через VPN.** В веб-интерфейсе («Интернет» → «Приоритеты подключений»)
  VPN-подключение (WireGuard, OpenVPN и т.п.) должно стоять выше провайдера. Скрипт не трогает
  основной маршрут, он только отправляет российские сети мимо него — напрямую через провайдера.
  Если основное подключение — провайдер, ничего не сломается, но и смысла не будет.

## Установка

На роутере, в shell entware (`ssh -p 222 root@<IP роутера>`, на свежем entware пароль `keenetic` —
сразу смените его командой `passwd`):

```sh
opkg update && opkg install git git-http
git clone https://github.com/romc/keenetic-bootstrap.git /opt/root/keenetic-bootstrap
sh /opt/root/keenetic-bootstrap/setup.sh
```

Обновить: `cd /opt/root/keenetic-bootstrap && git pull && sh setup.sh`.
Удалить: `sh /opt/root/keenetic-bootstrap/setup.sh --uninstall` (с `--purge` — вместе со списками и кэшем).

## Как это работает

- `ru-routes-update` собирает список российских IPv4-сетей (~11,5 тыс. префиксов) из статистики пяти
  региональных регистраторов (RIPE NCC, APNIC, ARIN, LACNIC, AFRINIC) и GeoIP-списка runetfreedom
  и превращает его в маршруты через провайдера. Для Ethernet-подключения — через шлюз провайдера,
  для PPPoE/L2TP/PPTP — через сам интерфейс.
- **bird2** кладёт эти маршруты в отдельную таблицу ядра `1100`, а правило `ip rule 30100` (`S02ru-routes`)
  велит искать адрес сначала в ней. Всё, чего там нет, идёт по основному маршруту — через VPN.
- cron раз в 4 часа проверяет, изменились ли источники (скачивается только изменившееся), и обновляет
  маршруты в bird без перезапуска, если список поменялся.
- `/opt/etc/ru-routes/vpn-exceptions.conf` — исключения: адреса в российских сетях, которые всё равно
  должны идти через VPN, например `route 203.0.113.10/32 via "ovpn_br0";`. После правки — `birdc configure`.

Дополнительно (вопрос при установке или `--extras`): `cpuwatch` пишет в журнал роутера всплески загрузки
CPU и потери пинга через VPN и через провайдера; unreachable-маршруты для IPv6 Cloudflare не дают
клиентам обходить IPv4-VPN через IPv6.

## Что делает setup.sh

1. Проверки: entware на месте, запуск от root, свободно на `/opt` не меньше 100 МБ.
2. Показывает текущую установку, если она есть: интерфейс провайдера, правило, число маршрутов, bird,
   время обновления списков, куда сейчас идёт `77.88.8.8`.
3. Если на роутере есть Bird4Static, предупреждает: он использует те же механизмы и будет мешать.
   Заменить его — только с вашего согласия (`--replace-bird4static` без вопроса); его init-скрипт
   и задание cron переносятся в резервную папку, `bird.conf` сохраняется.
4. Спрашивает (Enter — значение по умолчанию): начинать ли установку; интерфейс провайдера — из списка
   подключений прошивки (по умолчанию PPPoE-подключение, если оно есть, иначе порт провайдера);
   ставить ли дополнения; качать ли списки сейчас.
5. Ставит пакеты (`bird2 bird2c curl iprange diffutils ip-full cron ca-bundle`), раскладывает файлы,
   запускает cron и bird, скачивает списки (1–3 минуты).
6. Проверяет: правило есть, bird и cron запущены, в таблице больше 1000 маршрутов,
   `77.88.8.8` идёт через интерфейс провайдера.

Без вопросов: `sh setup.sh -y [--isp ppp0] [--extras] [--no-update]`. Без терминала вопросы
тоже не задаются — берутся значения по умолчанию и флаги. Все флаги — `sh setup.sh --help`.

Запускать можно повторно: одинаковые файлы не трогаются, изменённые сохраняются как `*.bak-<время>`,
файл исключений не перезаписывается. Исходный `/opt/etc/bird.conf` сохраняется как
`bird.conf.before-ru-routes` и возвращается при `--uninstall`.

## Проверка

```sh
ip rule | grep 30100                  # 30100: from all lookup 1100
ip route show table 1100 | wc -l      # ~11500
ip route get 77.88.8.8                # через интерфейс провайдера, table 1100
ip route get 1.1.1.1                  # через VPN
cat /opt/var/lib/ru-routes/meta       # когда и из чего собран список
cat /opt/var/log/ru-routes.log        # обновления и ошибки cron
```

## Установка с компьютера

`install.sh` копирует набор на роутер по ssh и запускает там `setup.sh` (вопросы задаются в том же
терминале). Вместе с набором уезжают личные файлы из папки `local/` (она в `.gitignore`):

- `local/authorized_keys` — публичные ключи для входа на роутер по ssh;
- `local/vpn-exceptions.conf` — свои исключения (заменяют файл на роутере).

```sh
./install.sh -p 222 root@<IP роутера>
./install.sh backup root@<IP роутера>     # сохранить конфиг прошивки в local/backups/
```

Конфиг прошивки (`show running-config`: подключения, приоритеты, маршруты, пользователи) скрипт
не восстанавливает — его стоит сохранить до сброса и загрузить обратно в веб-интерфейсе
(«Управление» → «Параметры системы» → «Файлы»).
